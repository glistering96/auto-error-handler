# MVP 구현 작업 계획

기준: `ACCEPTED` ADR·의사결정 대장 → OpenAPI·JSON Schema → 구현 계약 → 실행 계획. 이 문서는 이번 구현의 진행 기록이며 확정 계약을 바꾸지 않는다.

## Phase 1 — 실행 기반

- [x] Python 3.12 패키지와 잠금 파일, API·작업자 진입점, 형식화된 설정을 만든다.
- [x] PostgreSQL 16 Compose, Alembic 스키마, 서비스 등록 명령과 상태 점검을 만든다.
- [x] 오류 응답·이벤트 스키마 계약 시험을 만든다.

## Phase 2 — 오류 접수와 사건

- [x] RFC 8785 체크섬, 중복 키·본문 크기·재현 데이터 제한을 검사한다.
- [x] 중복 이벤트를 Git 조회 전에 돌려주고 새 이벤트의 전체 SHA를 접수 때 고정한다.
- [x] 이벤트·사건·발생 기록·분석 작업을 원자적으로 저장하고 동시 사건 묶기를 시험한다.
- [x] 사건 목록·상세 조회를 계약에 맞춘다.

## Phase 3 — 작업자와 가짜 분석

- [x] `SKIP LOCKED` 선점, UUID `claim_token`, 생존 신호, 만료 회수·재시도를 구현한다.
- [x] 첫 이벤트와 정책 고정 사본을 첫 선점 때 저장하고 재시도에서 재사용한다.
- [x] 가짜 게이트웨이로 분석 상태 전이와 조회를 시험한다.

## Phase 4 — 실제 분석

- [x] 저장된 SHA의 새 읽기 전용 작업 트리와 Codex Python SDK 어댑터를 연결한다.
- [x] 로컬 Codex 로그인과 환경변수 API 키 경로를 지원한다.
- [x] 구조화 결과, 시간 초과, 변경 없음, 작업 트리 정리를 확인한다.

## Phase 5 — 승인과 패치

- [x] 본문 없는 멱등 승인으로 승인·패치 실행·작업을 원자적으로 저장한다.
- [x] 승인된 SHA·정책 고정 사본으로 별도 쓰기 가능 작업 트리에서 패치한다.
- [x] 실제 Git 변경 내역과 경로·유형·크기 정책을 검사한 뒤 등록 명령만 네트워크 격리 환경에서 실행한다.
- [x] 검증 결과와 변경 내역을 조회할 수 있게 한다.

## Phase 6 — 제품 검증

- [x] 예제 저장소로 전체 흐름을 반복 실행하고 중복·실패·임대 만료를 주입한다.
- [x] 실제 Codex 경로의 인증·샌드박스·명령 통신 차단을 확인하고, 임대 상실 시 작업자 취소를 시험한다.
- [x] README의 실행 명령과 검증 결과를 실제 동작에 맞춰 갱신한다.

구현 판단: API와 작업자는 별도 프로세스다. 일반 자동 시험은 가짜 게이트웨이를 사용한다. `GET /health/ready`는 DB·설정·인증·격리 실행 도구의 존재를 점검하며 모델 호출까지 수행하지 않는다. `vectors/`는 기존 미추적 데이터이므로 건드리지 않는다.

검증 기록: 로컬 Codex 로그인으로 실제 분석→승인→패치→등록 검증이 `PATCH_READY`까지 완료됐다. 실제 Codex 네트워크 탐침은 소켓 생성이 `PermissionError`로 차단됐다고 응답했다. `bwrap` 통신 차단과 임대 상실 시 작업 취소는 자동 시험으로 확인했다. API 키 방식은 사용 가능한 키가 없어 설정·환경 격리 시험까지만 확인했다.
