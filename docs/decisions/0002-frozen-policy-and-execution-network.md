# ADR-0002: 분석 정책 고정과 실행 환경의 외부 통신

- Status: Accepted
- Date: 2026-09-24
- Decision owner: Auto Error Handler MVP
- Related decision: DEC-013, DEC-022, DEC-023
- Supersedes: 없음

## 배경

`services.policy`는 분석 뒤 승인하거나 패치하기 전에 바뀔 수 있다. 현재 값을 패치에 다시 적용하면 승인자가 확인한 분석과 다른 허용 경로·검증 명령으로 변경을 만들 수 있다. 또한 Codex 앱 서버는 모델과 통신해야 하지만, 모델이 실행한 명령과 별도 검증 명령이 임의의 외부 주소에 접속할 필요는 없다.

## 검토한 선택지

- 승인 때 현재 정책을 다시 읽는다: 구현은 쉽지만 분석과 패치 사이의 정책 변경에 취약하다.
- 정책이 바뀌면 승인을 거부한다: 안전하지만 운영자가 정책을 갱신할 때 진행 중인 사건이 멈춘다.
- 분석 때 정책 고정 사본을 저장한다: 저장 공간이 조금 늘지만 승인 대상과 실행 조건이 일치한다.
- 모든 외부 통신을 막는다: 검증 명령에는 적합하지만 Codex 모델 호출도 막을 수 있다.

## 결정

1. 첫 분석 선점 때 사건에 저장된 `incidents.repository_path_snapshot`과 당시 `services.policy`를 검증하고 `analysis_runs.policy_snapshot`에 저장한다. 실행 지침 경로, 허용·차단 경로, 변경 파일·줄 수 제한, 검증 명령의 인자 배열과 시간 제한, 분석·패치 시간 제한, 모델, 구조화 결과 형식 버전, 실행 환경의 통신 규칙을 포함한다. 재시도는 같은 고정 사본을 사용한다.
2. 승인·패치·변경 내역 검사·검증 명령은 승인된 `analysis_run_id`의 `policy_snapshot`과 `base_commit_sha`만 사용한다. 현재 `services.policy`와 저장소 경로는 새로 시작하는 분석에만 적용된다. 별도의 정책 해시나 버전 테이블은 MVP에 추가하지 않는다. 분석 조회 API에는 비밀값과 내부 절대 경로를 뺀 정책 요약을 포함해 승인자가 적용 조건을 확인할 수 있게 한다.
3. Python `openai-codex`의 `AsyncCodex` 컨텍스트를 각 작업 시도마다 새로 열고 분석·패치에 각각 새 스레드를 사용한다. 분석은 `Sandbox.read_only`, 패치는 `Sandbox.workspace_write`로 실행한다. SDK와 함께 배포되는 Codex 실행 환경을 사용하고, 시험한 안정 버전을 구현 잠금 파일에 정확히 고정한다. 실제 취소·시간 초과·하위 프로세스 종료 동작은 고정한 버전으로 통합 시험을 통과해야 한다.
4. Codex 앱 서버가 모델 서비스와 통신하는 경로는 허용한다. 모델이 실행하는 셸 명령과 검증 명령의 외부 접속은 기본 차단한다. `workspace_write`의 명령 네트워크 접근을 끄고, 검증 명령은 별도 격리 실행 환경에서 네트워크를 차단한다. 패키지 내려받기와 `git fetch/pull/push`도 실행 단계에서 허용하지 않는다. 파일 샌드박스만으로 네트워크 차단을 증명했다고 간주하지 않는다.
5. 로컬 MVP는 사전에 준비한 저장소와 의존성으로 실행한다. 실행 환경이 모델 연결과 명령 통신을 분리해 강제할 수 없으면 실제 Codex 경로를 준비 완료로 표시하지 않는다. 가짜 게이트웨이의 일반 CI 시험은 계속 수행한다.

## 영향

- `analysis_runs`에 JSON 고정 사본이 추가된다. 서비스 정책 변경 뒤에도 이미 시작한 분석의 승인·패치 결과는 기존 조건을 따른다.
- 실행 환경 구성과 실제 SDK 통합 시험이 필요하다. 검증 명령에 인터넷이 필요한 서비스는 MVP 예제로 등록하지 않는다.
- 공식 OpenAI 문서의 Python SDK와 샌드박스 설정을 구현 시점에 다시 확인해야 한다: [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk), [에이전트 승인과 보안](https://learn.chatgpt.com/docs/agent-approvals-security).

## 검증

- 분석 후 `services.policy`를 완화하거나 강화해도 승인과 패치가 저장된 `policy_snapshot`만 사용하는지 확인한다.
- 재시도마다 새 Codex 스레드와 작업 트리를 사용하면서 정책 고정 사본은 유지하는지 확인한다.
- Codex 모델 호출은 성공하고, Codex가 실행한 명령과 검증 명령의 외부 접속은 실패하는지 각각 확인한다.
- 작업 취소·시간 초과 뒤 앱 서버와 하위 프로세스가 종료되고 작업 트리가 정리되는지 확인한다.
