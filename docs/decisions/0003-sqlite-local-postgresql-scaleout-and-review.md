# ADR-0003: 로컬 SQLite, 확장형 PostgreSQL, 읽기 전용 리뷰 웹

- 상태: ACCEPTED
- 날짜: 2026-09-25
- 관련 결정: DEC-003, DEC-012, DEC-019, DEC-026

## 결정

로컬 기본 실행에는 SQLite 파일 DB를 사용한다. 사건·실행·작업의 단일 기준 정보는 **선택한 DB 한 곳**이다. 여러 API·작업자를 여러 호스트에서 운영할 때는 PostgreSQL을 사용한다. DB URL을 제외한 API 계약과 사건 상태는 동일하게 유지한다.

SQLite는 WAL, 외래 키, 30초 쓰기 대기 시간을 사용한다. 모든 쓰기 트랜잭션은 `BEGIN IMMEDIATE`로 시작해 작업 선점과 멱등성 조회 후 저장을 직렬화한다. WAL은 읽기와 쓰기를 함께 진행할 수 있지만 쓰기 작업은 한 번에 하나이며 파일을 같은 호스트에 둬야 한다. 따라서 SQLite는 로컬 개발·소규모 단일 호스트 실행의 기본값으로 둔다.

PostgreSQL은 `FOR UPDATE SKIP LOCKED`로 작업을 선점하고 사건별 부분 고유 인덱스와 이벤트 고유 제약으로 동시 접수를 보호한다. 접수 중 서비스 설정은 공유 행 잠금으로 읽어 서로 다른 사건의 접수를 병렬로 허용한다. 고유 제약 충돌은 전체 트랜잭션을 제한 횟수 내 재시도한다. 미완료 작업 100개 상한의 자문 잠금은 PostgreSQL에서 사용하고 SQLite는 쓰기 트랜잭션 자체가 같은 역할을 한다.

서비스 설정에는 `REPOSITORY_ROOT` 아래의 상대 경로를 저장한다. 각 작업자는 자기 저장소 루트에서 같은 기준 SHA를 찾아야 한다. 기존 절대 경로 기록은 같은 루트에서 읽을 수 있도록 유지한다. 서비스 설정 등록은 명시적 CLI 명령으로 수행하며 API 시작 때 DB를 쓰지 않는다.

리뷰 웹은 별도 읽기 전용 프로세스로 실행한다. 사건 목록과 첫 이벤트, 분석·승인·패치·검증 기록을 보여준다. 개발 환경에서는 루프백 주소에만 바인딩하며 인증·승인 조작은 추가하지 않는다.

## 검증

- SQLite와 PostgreSQL에서 동일한 사건 흐름, 병렬 이벤트 중복·묶기, 작업 선점·회수, 승인 충돌, 다른 저장소 루트의 작업자 실행을 시험한다.
- 리뷰 HTML의 이벤트 문자열 이스케이프와 브라우저 목록·상세 화면을 확인한다.
