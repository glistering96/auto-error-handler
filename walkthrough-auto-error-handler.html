Auto Error Handler · Functional MVP

오류에서 검증된 diff까지

외부 연동을 넓게 만들기 전에, HTTP로 받은 오류와 재현 정보를 Codex가 분석하고 사용자 승인 뒤에만 안전한 패치를 만드는 수직 흐름을 검증합니다.

1

HTTP 오류 이벤트

서비스가 serviceKey, 오류 문구, stack trace, commit SHA와 선택적인 재현 절차·비식별 입력을 전송합니다.

2

Incident와 Job 저장

API가 eventId 멱등성과 fingerprint grouping을 적용하고 PostgreSQL에 Incident, occurrence, Analysis Job을 한 transaction으로 저장합니다.

3

읽기 전용 Codex 분석

Worker가 기준 commit의 read-only worktree에서 Python Codex SDK를 실행합니다. 원인, 코드 근거, 재현 가능성, 변경 제안과 회귀 테스트 계획을 저장합니다.

4

명시적 승인

사용자가 API에서 분석을 확인하고 승인합니다. MVP에서는 인증 없이 개발 환경에서만 동작합니다. 승인 전에는 writable worktree를 만들지 않습니다.

5

격리된 패치

승인에 묶인 SHA에서 새 worktree와 새 Codex thread를 시작합니다. 분석 결과와 허용 경로만 Patch Runner에 전달합니다.

6

정책·테스트 검증

실제 Git diff의 경로와 크기를 검사한 뒤 등록된 argv 명령만 실행합니다. 성공하면 diff와 검증 결과를 API로 제공합니다.

안전 경계

분석은 읽기 전용

Codex 분석 중 저장소 변경이 없어야 하며 종료 시 worktree를 삭제합니다.

승인이 쓰기 경계

승인 transaction이 성공한 경우에만 Patch Job을 생성합니다.

재현 정보는 힌트

Producer가 보낸 재현 문자열은 명령으로 실행하지 않습니다. 등록된 validation command만 실행합니다.

결과는 로컬 diff

MVP는 GitHub에 push하거나 운영 환경을 변경하지 않습니다.

지금 만들지 않는 것

서비스·사용자 인증 · 외부 RabbitMQ · 메신저 · GitHub App/PR · 멀티테넌시 · Kubernetes · 자동 배포

핵심 수직 흐름이 fixture 저장소에서 E2E로 검증된 뒤 필요한 순서대로 추가합니다.
